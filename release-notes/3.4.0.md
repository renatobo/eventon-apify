## New Features

- Developer hooks: `eventon_apify_event_saved` and `eventon_apify_event_deleted` actions, and `eventon_apify_format_event`, `eventon_apify_format_rsvp_attendee`, `eventon_apify_validate_event_payload`, and `eventon_apify_repeat_limits` filters. See "Developer hooks" in the README.
- New setting, **RSVP cleanup on event delete** (on by default). Permanently deleting an event already deleted its RSVP records; that behavior is now visible on the Event API tab and can be turned off. It applies to every permanent delete path, not only the API.

## Improvements

- Repeat input is bounded: `repeat.count` up to 500, `repeat.gap` up to 365, and at most 500 `repeat.intervals` items. Larger values return `400 eventon_apify_repeat_limit_exceeded` instead of letting one request expand an unbounded series. Sites can raise the limits with `eventon_apify_repeat_limits`; the MCP manifest and OpenAPI spec publish them.
- An unfiltered RSVP attendee list (`GET /events/<id>/rsvps` with no `rsvp`, `status`, `search`, `repeat_interval`, or `updated_after`) is now paged in SQL instead of loading every RSVP. Filtered lists and delta sync keep the previous path. Responses are identical.
- The RSVP summary reads only the four fields it needs (rsvp, status, headcount, repeat interval) through the same accessors as the attendee list, and no longer builds full attendee payloads.
- A created event is inserted as a draft and moved to its requested status only after its meta and terms are saved, so publish listeners (notifications, auto-posting, caches) never see an event without its dates.
- Event write rollback restores only what the failed write changed: post meta is diffed against the snapshot instead of deleted and re-added, and only the `evo_tax_meta` entries the write saved are put back, so a concurrent change to another term is no longer lost.
- The settings bootstrap that runs on every request returns early once the current version has bootstrapped, and the installed-version marker is autoloaded, so the check costs no query.
- RSVP delta-sync timestamps are written once per RSVP at the end of the request instead of once per changed meta key, and are taken after the last change.
- Uninstall cleans every site of a multisite network.
- `WP_Error` messages returned by event and taxonomy writes are translatable.

## Bug Fixes

- A database failure while creating or updating an event no longer returns the SQL error text (`$wpdb->last_error`) in the response body. Code and message are unchanged; the detail goes to the PHP error log.
- `wp/v2` compatibility mode no longer locks non-administrators out of routes EventON registers itself. EventON 5 exposes `ajde_events` and its `event_type` taxonomies on `wp/v2`; turning compatibility mode on used to return 401 to editors (breaking the block editor for events) and to anonymous readers of published events. The admin-only rule now applies only to routes compatibility mode adds; the EventON fields stay administrator-only.
- A missing EventON now returns `503` (a dependency outage the client can retry) instead of `500`.

## Notes

- Behavior changes to review before upgrading: the `wp/v2` access change above, the `503` status, the new `400` repeat limits, and create-as-draft-then-publish (a create that fails after insert is still rolled back).
- If you turned on `wp/v2` compatibility mode to hide EventON's own REST routes from the public, that side effect is gone: those routes now keep EventON's defaults, which allow anonymous reads of published events (drafts, private events, and event meta stay hidden, and writes still require EventON's administrator capabilities). Hiding them was never the setting's purpose. To keep them hidden, disable `show_in_rest` for `ajde_events` separately, for example with a `register_post_type_args` filter.
- No migration is needed. The new RSVP cleanup setting is seeded on, matching the previous behavior, including for installs whose settings backup predates it.
