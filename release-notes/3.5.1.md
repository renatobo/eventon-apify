## Bug Fixes

- `repeat.intervals` items with no readable start and end (a bare string, an empty object, `start_at` without `end_at`, or `start_timestamp` without `end_timestamp`) now return `400 eventon_apify_invalid_repeat_interval` naming the item's index, for example `repeat.intervals[1]`. They used to be dropped silently, so a custom series saved with fewer occurrences than the client sent and no error.

## Notes

- Clients that relied on unreadable interval items being ignored now get a 400 and should remove them from the request.
